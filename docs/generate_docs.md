## Інструменти

| Інструмент | Призначення |
|-----------|-------------|
| **JSDoc 4** | Генерація HTML документації з JS коментарів |
| **eslint-plugin-jsdoc** | Перевірка якості JSDoc коментарів |

## Встановлення

```bash
npm install
```

---

## Генерація документації

```bash
# Згенерувати документацію в docs/api/
npm run docs

# Перевірити якість JSDoc коментарів
npm run lint:js

# Повна перевірка (лінт + документація)
npm run check
```

Після генерації документація буде доступна в папці `docs/api/index.html`.

## Стандарти документування

### Обов'язкові теги для функцій

```js
/**
 * Короткий опис функції.
 *
 * @param {string} name - Опис параметру
 * @returns {boolean} Опис результату
 * @example
 * // Приклад використання
 * myFunction('test'); // => true
 */
```

### Обов'язкові теги для файлів

```js
/**
 * @fileoverview Опис призначення файлу.
 * @module назва-модуля
 * @author Gazman4iK1
 * @version 1.2.0
 */
```

### Обов'язкові теги для змінних

```js
/**
 * Опис змінної.
 * @type {HTMLElement|null}
 */
const element = document.getElementById('id');
```

### Правила для всіх учасників проєкту

- Кожна публічна функція **обов'язково** має JSDoc коментар
- Кожен файл **обов'язково** має `@fileoverview`
- Після будь-яких змін у коді — оновити документацію
- Запускати `npm run docs` перед кожним комітом

## Перевірка якості

Якість JSDoc перевіряється через `eslint-plugin-jsdoc`:

```bash
npm run lint:js
```

Правила перевірки (`.eslintrc.js`):
- `jsdoc/require-jsdoc` — обов'язкові коментарі для функцій
- `jsdoc/require-description` — обов'язковий опис
- `jsdoc/check-types` — перевірка типів

## CI/CD публікація

Документація автоматично публікується на GitHub Pages через `.github/workflows/docs.yml`.

При кожному push в `main`:
1. Встановлюються залежності (`npm install`)
2. Генерується документація (`npm run docs`)
3. Папка `docs/api` публікується на GitHub Pages

Документація доступна за адресою:
```
https://Gazman4iK1.github.io/techvolt-landing-v2/docs/api/
```
